# AMRE 设计决策

## ADR-001 · Research Problem 是持久研究单元

精确命题、假设、依赖和验收条件共同定义一个问题。合同由确定性程序加载和验证。
图谱在合同之上表达 AND/OR 依赖，使重试、变更假设和切换模型后仍能辨认同一个问题。

## ADR-002 · 单一核心模型与确定性协调

只为深度推理使用核心模型。配置、图查询、调度、预算、工件处理和出处检查在程序中完成。
模型运行须有明确授权，长程调度须受工作区、沙箱和预算约束。

## ADR-003 · Git 保存长期知识，SQLite 支持本地运行

把合同、证据、工件和检查点纳入 Git 可恢复记录，使用 SQLite 保存可重建索引和本地运行状态。
阶段 02 使用 NetworkX 构建内存研究图。阶段 03 以标准库 SQLite 从已发布研究文件重建索引。

## ADR-004 · 证据分类与验收分别建模

候选证明、计算检验、形式化证明和人工确认是不同的来源类别。Runner 输出候选工件，
合同验收依据证据来源及覆盖范围进行，证据等级只能由对应的出处记录支持。

## ADR-005 · Windows 原生 CLI 和显式配置

采用 Python 3.11+ 的 `src` 布局、`pyproject.toml` 和标准库 `argparse`。
用 PyYAML 安全加载本地文件、用 Pydantic 验证合并后的设置。环境变量可覆盖同名配置。
Codex CLI 作为可选探测项，安装、测试和 CI 使用确定性命令。

## ADR-006 · 工作区单快照与独立 LaTeX 工件

`research/research.yaml` 保存合同、原始图、假设声明和复核版本。合同引用映射成图边，
避免对同一个依赖维护两份数据。合同、图和快照分别声明 schema 版本。
Pydantic 拒绝未知字段，YAML 读取拒绝重复键。编号比较区分大小写，重复检测忽略大小写。

数学陈述用单独的 UTF-8 LaTeX 保存，引用绑定规范化换行后的 SHA-256。
CLI 生成的陈述以摘要命名，修改会写出新文件。存储层在跨进程锁下验证完整快照，
先发布新 LaTeX，再原子替换 YAML。写入中断可能留下无引用 LaTeX，旧快照仍可加载。
锁和原子替换适用于 AMRE 管理的本地文件写入。绕过 API 修改陈述会触发摘要不匹配。

## ADR-007 · 候选路线与证明归约

NetworkX 多重有向图允许同一对节点保留不同关系。逻辑依赖必须无环。
路线的所属断言和必要前提分别表达 OR 与 AND。每条路线保存归约陈述及单独证据，
因此输入完备仍需核对归约本身。证据或依赖数量不会提升断言状态。

## ADR-008 · 显式假设与失效传播

只使用显式假设 ID、声明的多前提蕴含和成对冲突。相似文字没有推理语义。
修改断言或关键依赖时，下游复核版本递增并标记 `NEEDS_RECHECK`。
修改所属断言或相关假设时，受影响的归约也须复核。只改变某条路线的引理时，
其他路线保持独立。旧证据保留其原版本，复核标记清除后仍须检查证据版本。

## ADR-009 · 证据来源、检查与适用范围

断言状态保留 `UNPROVED`、`PARTIAL`、`PROOF_CANDIDATE`、`REFUTATION_CANDIDATE`。
计算检验、形式化验证、人工确认是证据属性，由各自的来源类型支持。
路线评估只接受当前断言版本、完整覆盖且结果通过的形式化或人工确认记录作为证明支持。
证据显式区分 `SUPPORT` 和 `REFUTE`。达到同等标准的反驳会阻止受影响路线被判为就绪。
模型来源记录允许登记为候选证据。

阶段 02 检查字段、断言绑定、版本和本地工件存在性。Git 修订可用于记录来源，
未提交工件的修订可留空。可信工具调用、人工确认身份和合同级验收由后续实现处理。

## ADR-010 · 事件、归档和检查点的提交边界

`research/events/` 按事件 ID 保存不可变 YAML，`research/checkpoints/` 保存 schema
版本化的检查点。事件顺序由研究清单的 `event_ids` 决定，序号和引用在重放时校验。
研究操作先发布工件、事件与检查点，再原子替换清单。崩溃留下的未引用文件不参与恢复。

`research/archive/` 保存按 SHA-256 去重的原始字节。事件保存所引用的工件和适用的合同或
图节点快照；检查点冻结单个问题的相关图、证据和选定上下文来源。Git HEAD 在保存时读取，
尚无提交时为空。恢复使用已发布检查点的工件，即使原始文件已变化；同时返回当前工作区
与归档是否匹配。恢复只读，保留当前工作区的合同与图。

## ADR-011 · 独立的事件重放和可重建索引

合同创建、相关证据登记及检查点创建自动产生事件。尝试、候选断言、障碍、路线切换和暂停
使用显式事件。重放根据顺序重建最近尝试、暂停状态、路线和检查点，拒绝孤立完成或重叠尝试。
旧工作区可从空事件序列继续使用。SQLite 在验证研究文件后重建，可删除或替换损坏索引。

## ADR-012 · 以完整研究段落装配上下文

上下文的预算采用 UTF-8 字节。必需段落保存精确陈述、假设、定义、当前目标、活动路线及
关键依赖引用。可选段落包括依赖明细、障碍、失败与已排除方法、推导及文献。预算不足时整块
省略可选内容，必需内容无法放入时返回明确错误。上下文从相关子图及显式选定的文本工件构建。
阶段 03 测试跨进程文件恢复和确定性装配。真实模型会话集成属于后续阶段。

## ADR-013 · 执行预留、回执与恢复

执行账本采用原子 YAML 和工作区单工作者锁。单独的短时账本锁允许另一个 CLI 进程提交
暂停或停止请求。尝试 ID 和预算预留先于派发持久化，回执先于研究状态发布。
重启可继续发布已存在的回执。无回执的尝试按预留时长结算，并保存可诊断的中断状态。

研究证据、障碍与事件复用阶段 02–03 的图谱和提交协议。发布新证据前核对原断言版本，
使用带预期快照的合同更新避免并发覆盖。候选工件经由受限名称和 UTF-8 数据写入尝试目录。

## ADR-014 · 模型适配和保守限额

离线 Mock 是默认适配器。真实 CLI 需 `--adapter codex --live` 双开关，拒绝 Codex 内嵌套
运行。适配器基于本机帮助和 feature 探测，使用隔离工作目录、只读沙箱配置、受限环境、
参数数组和有界输出。超时与取消请求终止本地子进程，原始流保存脱敏版本。
本机支持 JSONL 输出，按已完成消息和明确返回的用量字段解析。参见
[OpenAI Docs 的 Codex CLI JSONL 示例](https://developers.openai.com/blog/eval-skills)。

次数、时长和单工作者并发由本地账本控制。模型尝试采用无工具约定，意外工具事件会被拒收。
可获得的 token 用量在响应后入账，缺失的 token 或费用保留未知状态。

## ADR-015 · 技能契约与兼容的研究回执

七种技能各自选择范围内的输入并验证专用输出。阶段 04 的通用回执和图文件按可选字段兼容，
带 `--mode` 的运行额外校验模式、前置断言、证据、数学工件定位和同模型自检。
所有技能继续经同一个 `ModelAdapter` 派发。候选引理和归约通过原图模型及独立候选证据接入。

## ADR-016 · 障碍身份、方法切换和进展

障碍身份使用问题及断言版本、类别、精确数学步骤、失败方法和排除范围。精确重现追加尝试
及证据、递增版本，已有失败工件保留。文字匹配只供候选检索。解除障碍需指向范围精确、
当前有效的独立支持证据，原图边保留供追溯。

每个进展条目同时引用原始文件和证据 ID。已满足义务要求范围匹配的独立证据，
候选归约、候选推导、障碍和重复文本各有独立类型。进展工件随尝试完成事件提交和归档，
可从原回执和 Checkpoint 幂等恢复。

## ADR-017 · Deep Research 默认工作流

同一 Research Contract 的深度会话是默认执行单位。Skill 可在一次连续派发内切换，
原尝试、预算、图谱和 Checkpoint 接口继续提供持久化与安全约束。显式短任务复用原路径。
宏观调度关注实质进展、停滞与资源边界。语义事件保存原始推导和假设，并区分适配器会话
接续与文件上下文重建。

本机 Codex CLI 0.167.0 的 `codex exec resume --help` 明确支持指定会话 ID，
`--ephemeral` 运行不会持久化会话。显式配置允许 Codex 保存本地历史。
适配器通过 CLI 预检选择接续命令并用提供方事件核对会话 ID。同一派发最多启动一次模型，
接续启动后出现异常由账本和 Checkpoint 处理。Mock 验证连续控制流和文件恢复。
真实 Codex 认证、Windows 沙箱和服务端会话接续须单独验收。

## ADR-018 · 宏观路线调度与归档

调度以结构化图谱、作用域、候选数学进展和实际结算为输入。当前路线在最近一次取得
有源进展或刚遇到单个局部障碍时优先延续。耗尽限额、明确阻塞或结构化停滞后的冷却
优先于连续性。其余候选依据可配置的 60/25/15 派发份额及启发式排序。
默认探索会话最多 120 秒，仍受合同和全局预算约束。离线验收可显式缩短测试限额。

决策保存完整输入和固定种子，可验证重放；模拟仅在内存中预留和结算。路线切换在派发前
保存原路线和新路线，尝试结算后再保存一次。派生合同使用精确陈述和作用域去重，
并检查父链深度、子合同数量及前置依赖。

## ADR-019 · 文献版本与可追踪选题

文献、引用和候选选题沿用 ResearchStore 的事务，数学陈述使用内容寻址的 LaTeX。
DOI 和 arXiv ID 用于合并书目，保留来源及版本。提取的数学陈述固定到具体来源版本和位置，
其图谱引用可传播复核状态。确认来源需要人工核对和可读取的授权摘录，只保存核对摘要和摘录
摘要值。来源确认与数学证据属性独立。

在线搜索默认关闭，只获取元数据。端点固定，缓存和限流文件保存在 `.amre/`。
候选选题保留精确陈述、条件及验证标准，开放性和新颖性保持未确认。
会话内文献查询通过有预算、允许列表和不可变回执的宿主工具桥从离线目录读取。
Provider 依据 [arXiv API 手册](https://info.arxiv.org/help/api/user-manual.html)、
[Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) 与
[Semantic Scholar Academic Graph API](https://api.semanticscholar.org/api-docs/graph)。

## ADR-020 · GR 数学工具与证据边界

用小型表达式语法构建 SymPy 表达式，并在有界子进程中执行。曲率输出包含约定版本、
指标顺序、坐标图和适用域。数值计算报告精度、分辨率和局部误差指标。规范兼容性、
一般约束传播和边界正则性保留为证明义务。

原始计算档案不可变。同一会话中的工具结果先保存档案和工具回执，随后在结算时注册
到已绑定断言的当前版本。计算证据的覆盖范围为 PARTIAL，工具失败记录为范围明确的障碍。
可选后端未配置时返回 UNAVAILABLE。

## ADR-021 · Dashboard 公开快照

公开快照只包含版本化协议定义的字段。用户明确选择问题、可发布的陈述和文字详情。
导出过滤凭据及私有路径，工件默认以分类和证据级别呈现。Vite 构建只接收公开快照，
关闭通用静态目录复制。交互图谱保留 AND/OR 方向和引用，KaTeX 禁用受信内容。
GitHub Pages 部署使用独立的手动工作流和可选发布开关。

## ADR-022 · 离线基准和可回滚策略

已知数学结论和脚本化的候选研究轨迹分开统计。Deep 和 Short 使用相同适配器、
题目、工具检查与硬预算。短任务的历史检索消融只关闭模型输入的历史内容，
继续保存安全审计和预算账本。固定路线与自适应路线使用同一个停滞场景。

策略版本和评估记录按内容标识。只有通过隔离评估、匹配当前基准版本且由用户显式
执行 apply 的配置才能生效。激活记录可回退，评估不修改生产源代码。

## ADR-023 · Codex 会话内受限工具

真实适配器显式启动且配有工具配额时，只注册一个经过鉴权的回环 MCP 入口。
按派发生成凭据并在退出时关闭入口。工具调用复用会话预算、输入校验和不可变回执，
禁用探测到的其他 MCP 服务。替身传输验收覆盖真实回环 HTTP、鉴权与文件归档。
服务端工具协商和实际付费模型运行仍待独立验证。

[OpenAI Codex MCP 配置](https://developers.openai.com/codex/mcp/)与
[MCP Streamable HTTP 协议](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。
