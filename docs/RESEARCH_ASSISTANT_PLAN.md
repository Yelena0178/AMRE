# 五角色研究助理：实施计划

状态：PLANNED。本文是下一轮开发方案，不表示五个 Agent 或统一界面已经实现。
范围：研究入口、材料与 Intake、建档、运行管家、结果解读五个角色，共同构成一个研究入口。
对应开发总 Prompt 与运行时角色 Prompt 见 [Prompt 包](RESEARCH_ASSISTANT_PROMPTS.md)。
从新建项目到持续研究、成果验证和归档的产品流程见 [完整用户旅程](RESEARCH_USER_JOURNEY.md)。
其中新增的项目管理、周期规划和成果发布能力属于后续范围建议，尚未计为已实现功能。

## 产品目标

用户通过自然语言和文件附件完成：提出问题、澄清条件、修订草案、采用任务、授权运行、
查询进度、暂停恢复、阅读结果。正常流程不要求用户处理 YAML、JSON、路径、节点 ID 或命令。
必要决定集中呈现：研究目标及数学条件、采用哪一版任务、执行授权及预算、结果如何验收。
用户已明确授权的行为直接继续，不重复确认同一范围内的步骤。

五个角色复用同一个核心模型和现有 ModelAdapter。角色交接不创建独立模型工作者、
审查 Agent 或角色间聊天。程序负责路由约束、工具调用、权限、事务、版本和运行状态。
纯状态查询、预算计算和进程轮询优先由程序完成，不为每次轮询调用模型。

## 现有基础与缺口

| 环节 | 复用的当前基础 | 此次需要增加 |
| --- | --- | --- |
| 材料和草案 | `intake/` 的导入、准备、生成、接收和版本校验 | 会话内衔接、草案摘要、后台管理请求和答复 |
| 正式建档 | ResearchStore、ContractInput、研究图与原子发布 | 草案转换、引用解析、建档预览、绑定版本的采用操作 |
| 研究执行 | DeepResearchRunner、ResearchOrchestrator、TaskQueue、预算和检查点 | 用户授权记录、自然语言控制、真实状态投影 |
| 结果 | 报告、工件、证据和计算回执 | 面向用户的结果卡片及出处导航 |
| 用户入口 | 当前 CLI 与只读 Dashboard | 统一会话服务和本地研究对话界面 |

现有 Dashboard 保持只读；新的研究对话入口通过后台受控服务执行操作。
CLI 与界面共用同一服务层，避免出现两套建档或运行逻辑。

## A1：会话、权限与角色协议

交付：可持久化的会话控制器和薄 CLI 会话入口，尚不要求 Web 界面。

会话保存当前问题、草案/合同/检查点版本、用户消息、已经决定的条件、待确认事项、
授权范围、操作回执及最近进度。不同问题可以切换焦点，不能串用材料或预算。

建议在 `src/amre/assistant/` 定义 Pydantic 协议及控制器；实施前按实际接口调整布局。
每轮输入提供：当前用户消息、权威状态、已决定事项、必要来源、允许工具和授权记录。
模型每轮返回：面向用户的说明，以及至多一个工具请求或角色交接；没有动作则只回答。
模型返回内容不是执行回执，不允许模型生成一个 `authorized=true` 就获得权限。

授权记录由宿主绑定真实用户消息，记录操作、工作区、任务版本、允许角色用途、时间/调用/
token 上限及有效范围。材料、工具输出和模型总结均不能授予权限。
对“按这版开始”可以一次衔接采用和启动；缺少必要预算时只集中补问缺失信息。
授权过期、超出范围或任务实质变更时再请求决定。预算不能由模型自行提高。

验收：问题切换不串状态；材料内指令不能伪造授权；无权限动作被宿主拒绝；
重复用户事件不重复执行；从已保存记录恢复当前焦点和已决定事项。

## A2：研究入口与 Intake Agent

交付：用户直接提交问题/附件、回答澄清问题或要求修改，后台完成现有 Intake 操作。

入口角色判定新建、补充材料、修订、采用、运行、查询、暂停、停止和恢复等意图。
含糊的“继续”先读取当前状态；只有存在多个合理目标时才追问。
Intake 角色生成草案和变更摘要，自动处理请求 ID、响应 JSON 与归档路径。
草案显示用户条件、材料陈述、模型选择和未决问题；重要条件必须有出处或解释。

“你自己定”在上下文范围内授权作选择。将选择和理由写入草案，不将它改标为用户原话，
也不将它解释成付费运行授权。非关键排版问题不打断用户。

验收：原 Hawking 质量输入、真实澄清“你自己定”及两版草案可在会话入口复现；
新流程无需手动复制 JSON；保留原目标、质量定义、正性条件和所选归一化的来源。
已有 Intake v1 的独立命令、文件格式和历史版本仍可读取。

## A3：建档 Agent

交付：草案到正式合同的预览与原子提交，用户不手动编写节点或引用。

建档预览必须绑定草案版本、来源哈希与正式工作区基线，显示将新增/复用/变更的对象、
条件和未决阻碍。稳定 ID 由程序分配；模型提出映射建议，程序核对类型及引用。
只登记所需的假设、定义和已确认依赖，不自动编造证明分解或已成立的引理。
模型建议的必要条件必须在采用摘要中显式显示；无授权不得静默改变数学目标。

沿用 ResearchStore 的事务与期望基线检查。并发修改、旧草案或引用失效时，
返回具体差异，不覆盖或默默删除依赖。重复采用同一版本应返回已有结果。
阻碍执行的未决项需解决；仅影响未来展示等事项可以继续保留。
采用合同不升级任何证明证据。预算使用已授权配置，缺失时不得凭空补造。

验收：空工作区和已有工作区均可建档；合同重载和现有校验通过；来源可回溯；
重复采用、版本过期、同名引用、缺失前提和事务中断均有明确行为。

## A4：运行管家 Agent

交付：执行方案、授权内启动、进度查询、暂停/停止/恢复及可恢复回执。

默认衔接 Deep Research，保留显式短任务入口。执行方案列出目标、输入、验证步骤和限额。
宿主在派发前核对授权、上下文、工作区及预算。关键材料没有进入模型输入时，
先说明并修复，不让模型仅凭图上的引用 ID 继续。

复用单工作者锁、预算账本、派发 ID、模型沙箱和现有恢复流程。
进度来自实际语义事件、检查点或进程状态；没有新事件时显示最近记录的时间，不能编造进展。
暂停/停止是否完成以实际状态为准。进程情况不明时检查现有句柄和回执，
不把历史 RUNNING 文件当成存活证明，也不自动重新调用可能已计费的模型。

验收：无授权不启动；已授权不重复询问；超时、输出超限、未知用量和预算不足可解释；
双击启动不重复派发；暂停后冷恢复；在途崩溃不重复结算；停止后不暗中继续。
保留嵌套 Codex 禁止规则，不能为完成测试删除该保护。

## A5：结果解读 Agent 与统一界面

交付：基于真实工件和回执的结果卡，以及完整可操作的本地研究对话入口。

结果卡展示结论、关键论证、检查范围、未决问题、证据等级和来源。
模型新写的推理标为候选；符号代数检查只覆盖相应恒等式；不自动标记人工或形式化确认。
七种研究 Skill 是同一会话内的策略，不在界面中要求用户自行调度。

界面可复用现有 React/TypeScript 技术栈，研究对话部分与公开 Dashboard 分离。
本地服务默认只监听回环地址。界面包含对话区、当前任务卡、材料/版本/预算/结果抽屉。
状态至少区分：准备中、待澄清、可执行、等待授权、运行中、暂停请求中、已暂停、
停止请求中、已停止、执行失败、结果待核验、已结束。全部从权威记录投影。
用户不需要选择当前 Agent；角色名可以作为可展开的处理记录。
未授权材料不得进入公开快照，发布和 GitHub 同步仍遵守原有授权边界。

验收：用户从界面完成问题提交、修改、采用、启动、查询和查看结果；
暂停/恢复在界面与 CLI 状态一致；刷新或重启不丢焦点；结果能跳转到实际证据工件。

## A6：端到端验收与真实服务门槛

五个角色共同验收，不能仅以接口存在或角色名称出现宣称完成。
首次贯穿问题使用用户的 Hawking 质量题及已选定约定。未来的用户采用/运行授权必须实际取得，
不能把此前“你自己定”扩展为新的运行或付费授权。

在约束系数为 1 的所选归一化下，数学验收检查预期为：

\[
m_u=-2r^2\Omega^{-2}r_v\phi_u^2,\qquad
m_v=-2r^2\Omega^{-2}r_u\phi_v^2.
\]

要求实际模型工件完整展示质量求导、半径方程和对应约束的代入，以及各组抵消项。
用可重演的 SymPy 程序核对原始导数减去目标表达式为零，并保留运行结果。
不能增加 r_u、r_v 的符号/非零假设，不能通过除以它们缩小适用范围。
测试期望与夹具只用于验收，生产代码不得按问题名称返回现成答案。

验证分层记录：

1. 确定性/离线替身：验证协议、路由、权限、版本、工作流和失败恢复。
2. 当前会话或外部答复：验证实际任务草案与结果内容，明确身份和用量局限。
3. 真实适配器：用户单独授权后，在允许的独立运行环境调用真实服务，记录任务、
   模型返回身份、使用量、沙箱、回执及实际检查结果。

第一层通过不能替代第三层。未完成真实运行时，本地功能与真实服务的状态分别记录，
不宣称真实研究链路已经打通。每步先运行窄测试，最终运行全量回归及必要的界面验收。

## 实施顺序与交付标准

顺序为 A1 → A2 → A3 → A4 → A5 → A6。A5 的展示工作可以提前做最小界面，
但操作必须依赖已验证服务，不能先铺设固定演示流程。
这是一个五角色共同交付的功能包，不是五个彼此孤立的聊天框。

每个阶段在 IMPLEMENTATION_STATUS 中记录状态、环境、命令、结果、阻碍和恢复入口。
重要决策写入新增 ADR，保留既有 Intake v1 和研究模块行为。
本方案不授权当前直接实施、付费运行、提交推送或发布网站；实施授权由后续开发请求给出。
