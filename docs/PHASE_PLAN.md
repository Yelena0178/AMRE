# 阶段 04–10 验收计划

本计划叠加在 AMRE 04–10 总任务书上。既有离线交付和验收记录保留。新增的 Deep Research
门槛与原功能门槛均需验收通过后才进入下一阶段。

| 阶段 | Deep Research 集成 | 必须实测 |
| --- | --- | --- |
| 04 | `deep` 默认入口，连续会话、语义保存、预算与中断恢复，显式 `short` | 单次 Mock 派发完成多个引理步骤与策略变化；运行时保存，暂停/停止，崩溃后重建；三层限额、超时及重复恢复不重复结算；本机 CLI 会话能力与真实验证分开报告 |
| 05 | 七种 Skill 作为同会话可切换策略；失败记忆按重要语义事件保存 | 会话中使用不同数学策略并保留假设、原始推导、证据和未决义务；候选成果保持其证据等级 |
| 06 | 宏观调度，维持有实质进展的路线 | 单轮无定理或局部障碍不触发换线；结构化停滞、重大问题或边界触发有理由的决策；原 A/B/C、派生、预算、确定性重放与崩溃恢复验收 |
| 07 | 有界的文献查询能力在研究会话内部可用 | 同会话发起查询并接收带来源的结果，保持原文、证据和候选区分；原离线索引、选题、冲突和失败测试 |
| 08 | 有界 GR 计算能力在研究会话内部可用 | 同会话调用允许的数学计算，引用可重演结果；原 Minkowski、二球面、波动能量、约定与证据测试 |
| 09 | Dashboard 展示深度会话、时长、Checkpoints、路线变化 | 静态导出关联实际记录；核对状态和时长，保留脱敏和发布边界；本地构建及离线浏览 |
| 10 | 增加 Deep Research 与 Short Task Workflow 对照基准 | 相同模型适配器、工具与可比预算；比较数学进展、上下文损失、重复失败、消耗和完成情况；保留全流程集成及发布报告 |

自动化验收默认使用离线 Mock。真实模型仅能在明确授权的单独运行中调用。
独立证据由确定性程序和已有审查来源判断，使用一个核心推理模型。

Dashboard 的公开快照由显式的问题和工件选择构造。缺省只导出允许发布的结构化字段。
精确陈述、开放义务、障碍详情和引用文字须分别授权，构建不读取整个研究目录。
Windows 和 Linux 采用同一个版本化快照协议。GitHub Pages 工作流只处理明确提供的
公开选择，实际部署独立触发。
